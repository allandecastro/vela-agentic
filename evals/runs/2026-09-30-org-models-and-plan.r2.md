## Findings against the skills
1. minor: `skills/vela-apply/SKILL.md` step 5 says the plan's `operations` "must contain **only** what the Canvas ships (a scaffold demo left in shows up as extra `create` operations)".
   - What the skill misses: it only anticipates extra `create`s. It says nothing about a `delete` operation ("Exists in Dataverse but not locally"). That operation appears when the org already holds an assembly with the same name. The scaffold names the assembly `<prefix>.Plugins`, so two projects on the same prefix in one org would replace each other.
   - What happened: the actor read the delete correctly and blocked the gate with a question, but on its own judgement, not from skill guidance.
   - Suggested fix: state in step 5 that any `delete`/`update` operation on something the Canvas does not own is a gate blocker to surface to the human.
2. minor, Vela gap to flag and not work around: `skills/vela-plan-review/SKILL.md` ("reuse vs new") only checks for reuse against the repository.
   - The name collision with an existing org assembly was invisible until PREVIEW, because `vela plan` and `vela inspect` need a built package. Build Report L53 and L75 record the correction.
   - Vela has no package-less read of the org's plugin assemblies and steps for an entity, so the CHALLENGE step cannot check reuse against the org. Report this to the Vela repo.
