# The deploy guard (hooks)

This page describes the optional hooks that ship with the pack: what they deny, how a human approves a deploy, and
their limits. It is for whoever installs the pack and decides how much to trust an agent with an org connection.

A skill asks the agent to behave; a hook is run by the host, not the model. The pack works without the hooks. With
them, the rules below are enforced on Claude Code and GitHub Copilot CLI from the same scripts.

## What the guard denies

The guard runs before each shell command and file write.

| Rule | Denied | Allowed |
| --- | --- | --- |
| apply | `vela apply`, and `--auto-approve` or `--yes` on a `vela` command, unless the host was started with `VELA_APPLY_APPROVED=1` | `vela plan`, `vela apply --help`, text that only mentions the command |
| generated | Writing under `Models/Generated/`, a `*.g.cs` or `*.generated.cs` file, or a file marked `<auto-generated` | Every other file |
| git | A push to `main` or `master`, a forced push, `--no-verify` | A branch push, `--force-with-lease` off `main` and `master` |
| secrets | A secret literal in a command or a written file, printing the environment | `--client-secret "$VAR"`, `--secure-config Name=@file` |

The messages name the kind of secret, never its value.

## The session check

At session start a second hook compares the installed `vela` CLI with the version the pack was verified against,
and tells the agent to ask for `vela update` when it is older, or that the CLI is missing. It never blocks.

## Approve a deploy

Set `VELA_APPLY_APPROVED=1` in the environment the host was started from, for a run you have authorized:

```bash
VELA_APPLY_APPROVED=1 claude      # Claude Code
VELA_APPLY_APPROVED=1 copilot     # GitHub Copilot CLI
```

The variable opens the apply rule only; the other rules always hold. An inline prefix the agent types, such as
`VELA_APPLY_APPROVED=1 vela apply ...`, does not count: the agent cannot approve itself.

## Install and check

- **Claude Code:** active when the plugin is installed.
- **GitHub Copilot CLI:** active when the plugin is installed. In a trusted folder, the repository's
  `.github/copilot/settings.json` also loads it. After installing, ask the agent to run `vela apply -p x.nupkg` once
  and confirm it is blocked.
- **VS Code Copilot Chat** has no hooks.

The scripts need only POSIX `sh`, `awk`, `grep`, `sort` and `base64`: macOS, Linux and Git Bash on Windows. Windows
is not yet verified live.

## Limits

The guard is a guardrail, not a sandbox. Indirection, such as a variable holding the command or a script file that
runs `vela apply`, is not caught. Copilot pre-tool hooks let a call through when they time out. The real barriers
stay in place: the CLI's own typed `yes` confirmation, its refusal of a non-interactive apply without
`--auto-approve`, and not giving the agent credentials that can write to a production org.

The full rules, the wiring per host and the live verification are in
[`hooks/README.md`](https://github.com/allandecastro/vela-agentic/blob/v0.6.0/hooks/README.md).
